# 系统设计

## 核心定义

MaaS 的核心不是给模型套一层 HTTP，而是把异构、昂贵且不稳定的模型能力封装成可治理、可度量、可运营的标准化服务。

## 控制面

控制面负责低频、强一致的管理操作：

- 供应商和物理模型注册
- 虚拟模型与路由策略
- 租户、密钥、权限和配额
- 发布、灰度、回滚和下线
- 用量、账单和评测查询

## 数据面

数据面负责高频、低延迟的实时请求：

```text
请求 → 鉴权 → 路由定价 → 限流 → 配额预占 → 模型适配器 → 配额结算 → 计量/观测
```

请求热路径最终只读取本地配置快照和 Redis，不依赖控制面的实时可用性。

## 虚拟模型

客户端调用 `smart-chat`，网关根据策略选择实际模型。虚拟模型使业务应用与供应商、版本、价格和部署位置解耦。

## 当前实现边界

本地默认使用内存实现保证链路开箱即用；控制面可切换到 PostgreSQL 持久化租户、密钥和配额。Redis 可作为多网关实例共享的限流状态。PostgreSQL 不进入网关请求热路径，网关只读取本地鉴权快照和 Redis。
